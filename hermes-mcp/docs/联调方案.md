# Hermes 问数 — 数据源模块联调方案

> 版本：v0.1　状态：待执行　日期：2026-10-10
> 关联文档：`docs/数据源对接规范.md`（共享契约）· `docs/完整方案.md`（总设计）· `scripts/verify_contract.py`（验收探针）
> 参与方：**问数侧（hermes-mcp，我们）** ✕ **配置页侧（同事）** ＋ **DBA（只读账号）**

---

## 1. 联调目标

验证一条可端到端验收的链路：**同事在「数据源配置」页新增连接 → 写入共享 `db_connections.db` → 问数侧用同一个 key 解出任何密码 → 真实连库出数**。没有 HTTP 对调，本质是**对同一共享文件的「你写我读、我解你密」一致性验证**。

联调成功的**客观判据**：
- 共享文件里，两侧读到同一批连接；
- 问数侧对每条非空密码用共享 key 解出 `OK`；
- 对真库（SELECT-only）`SELECT 1` 能连上；
- 最终在问数侧用自然语言/工具问出正确数据。

---

## 2. 参与方与分工

| 方 | 职责 | 交付/输入 |
|---|---|---|
| **我们（hermes-mcp）** | 提供只读问数端、共享契约的权威实现、验收探针 | `hermes_mcp` 包、`verify_contract.py`、本方案 |
| **同事（配置页）** | 写共享 SQLite、提供「数据源配置」界面与 CRUD/测连通接口 | 能写 `db_connections.db` 的运行态配置页 |
| **DBA** | 提供**非生产库**的 SELECT-only 只读账号 | 连接串 + 只读账号（不落对话） |

> 我们的核心诉求对同事：**优先 `import hermes_mcp.store.ConnectionStore` 复用**，不要重写加密/读表（见对接规范 §4/§9）。这能把「加密漂移」这个最大风险直接消掉。

---

## 3. 前置条件（不满足不要开测）

1. **同机同一路径**：两侧 `HERMESMCP_DB_CONFIG` 指向**同一个** `db_connections.db`。联调期建议**两套都跑在联调机**上；跨机共享 SQLite 不成立（见对接规范 §2）。
2. **同一个 `HERMESMCP_DB_KEY`**：加密 key 两侧一致。key 只配到两侧环境，**不贴进对话/仓库**。
3. **方言 driver 就绪**（要 `--test` 真连）：mysql→`pymysql`、postgresql→`psycopg`、sqlserver→`pyodbc`（含 ODBC Driver）、oracle→`oracledb`。接到哪种就先装哪种。
4. **只用非生产 SELECT-only 账号**做联调，真连 `${库}` 时确认账号只授读。
5. **SQLite 开 WAL**，避免多进程读写锁冲突。

---

## 4. 联调期共享环境约定（两侧对齐）

| 项 | 约定值 | 说明 |
|---|---|---|
| 共享文件 | `HERMESMCP_DB_CONFIG` 指向的路径 | 两侧相同 |
| 加密 key | `HERMESMCP_DB_KEY` | 两侧相同，私下分发 |
| 真库连接 | `类型=mysql/pg…` + SELECT-only 账号 | 先 1 个非生产库，通过后再扩 |
| 验收探针 | `scripts/verify_contract.py` | 两侧共用 |

---

## 5. 分阶段联调步骤

### 阶段 A：静态契约对齐（不连库，必先过）
1. 同事配置页后端接入共享 `db_connections.db`（复用 `ConnectionStore` 或按其字段/加密写）。
2. 我们确认探针能读共享文件：
   ```bash
   python scripts/verify_contract.py --key "$HERMESMCP_DB_KEY"
   ```
   预期：列出连接、能解密的 `decrypt: OK`。**这一步不通过就不进入下面阶段。**

### 阶段 B：写 → 读 → 解 → 连（核心冒烟）
3. 同事在配置页**新增一个非生产 SELECT-only 连接**（如命名 `订单库`）。
4. 我们：
   ```bash
   python scripts/verify_contract.py --key "$HERMESMCP_DB_KEY" --connection 订单库 --test
   ```
   预期：
   - 能看到这条记录，`read_only=True`、`has_password=True`；
   - `decrypt: OK`（证明加密格式互通）；
   - `connect: OK (SELECT 1)`（证明真能连库出数）。
5. **反向**：我们用 `register_connection` 写入一条（如样例 sqlite），请同事在配置页仅只读地看到并**不回显密码**。证明双向一致性 + 保密。

### 阶段 C：业务级验证（用问数端真实出数）
6. 对连通连接：
   ```bash
   python - <<'PY'
   from hermes_mcp.server import get_schema_map, query
   print(get_schema_map("订单库"))   # 表结构
   print(query("订单库", "SELECT COUNT(*) FROM ..."))
   PY
   ```
   预期：结构可探、聚合查询返回真实数据、返回里带 `sql` 供抽查。
7. （可选）若生成模型 key 就绪，跑一次真实 `ask`：
   ```bash
   HERMESMCP_LLM_BASE_URL=... HERMESMCP_LLM_API_KEY=... python -c "from hermes_mcp.server import ask; print(ask('订单库','本月订单量'))"
   ```

### 阶段 D：状态联动
8. 同事点配置页「测连通」，确认 `status` 正确回写（`ok`/`error`），我们这边 `list_connections` 能看到该 `status`。确认双方对 `status/last_error` 字段的读写一致。

### 阶段 E：安全回归
9. 再次用探针跑全量（`--test`），确认没有密码明文、错 key 时 `decrypt: FAIL`、非只读连接被问数端拒绝。
10. 三方确认后，把共享环境约定（§4）固化为两侧 `.env`，结束联调。

## 6. 验收清单（可勾选）

- [ ] 共享文件同一路径，same file 两侧可见
- [ ] 配置页新增连接 → 问数侧 `list_connections` 可见（read_only=true、无明文密码）
- [ ] 非空密码用共享 key `decrypt: OK`
- [ ] 反方向（问数侧注册 → 配置页可见且不回显密码）
- [ ] 真库 `SELECT 1` `connect: OK`
- [ ] `get_schema_map` / `query` 返回正确数据 + SQL 回显
- [ ] 「测连通」`status` 两侧联动
- [ ] 错 key / 非只读 均被拦（FAIL / ReadOnlyViolation）
- [ ] key 与密码**未**在对话/日志/仓库/文件中以明文出现

## 7. 常见坑与对策

| 坑 | 现象 | 对策 |
|---|---|---|
| 加密漂移 | 能写进去、我们解不开（`decrypt: FAIL InvalidToken`） | 复用 `ConnectionStore`，别自己重写加密；过阶段 A |
| 两侧文件路径不一致 | 一边看不到另一边写的 | 用 `HERMESMCP_DB_CONFIG` 锚定，跑探针确认 `exists=True` 同路径 |
| key 不一致 | `decrypt: FAIL` | 核对两侧 `HERMESMCP_DB_KEY`；私下对齐 |
| 方言 driver 缺失 | `connect: FAIL (ModuleNotFoundError)` | 先 `pip install` 对应 driver 再 `--test` |
| 跨机共享 | 文件路径对不上一台机 | 联调期同机；跨机需改造为 REST/中心存储（后续） |
| 真库连不上/锁 | `connect: FAIL` | 用只读账号、确认网络/端口/库名；错误打码 |
| 锁冲突 | SQLite busy | 开 WAL |

---

## 8. 安全边界（联调期间铁律）

1. **key、密码、连接串 DSN 一律不贴进对话、不落仓库、不打明文日志**；探针与代码都保证不打印密码。
2. 联调只用**非生产库 + SELECT-only 账号**；`--test` 命中只读连接。
3. 出问题先查 `last_error`（打码），不要为了调试临时把 key/密码放进代码。
4. 联调期间共享文件与样例文件进 `.gitignore`（已有）。

---

## 9. 待定项 / 开放问题（联调前需定）

1. **联调机与路径**：`HERMESMCP_DB_CONFIG` 具体指向哪个文件、在哪台机，双方确认。
2. **key 分发方式**：`HERMESMCP_DB_KEY` 如何私下给到同事侧（两边的职责方定，不落文本）。
3. **首个真库**：用哪个非生产库 + SELECT-only 账号（DBA 提供）。
4. **同事是否复用我们的包**：若要复用，需给同事装 `hermes-mcp`（`pip install -e <目录>`）；若不复用，以对接规范字段/加密为准，靠阶段 A 兜底。
