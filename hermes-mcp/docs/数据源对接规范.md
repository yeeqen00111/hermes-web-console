# Hermes 问数 — 数据源（数据库连接）模块对接规范

> 交接对象：负责「数据源配置」管理页/接口的同事
> 目的：你的配置页往下写、hermes-mcp 问数端读取**同一个共享 SQLite**，本文件就是双方必须对齐的**唯一契约**。交给真正做配置页的人参考。
> 权威实现：见 `hermes-mcp` 包（`src/hermes_mcp/store.py` 读写表 + 加解密，`connections.py` 方言连接）。**强烈建议直接复用该包**，而不是照抄本规范重写加密/读写逻辑——这样不会漂移。

---

## 1. 数据流（谁写谁读）

```
[配置页 + 后端]  ──写──▶  共享 SQLite db_connections.db  ◀──读────  [hermes-mcp 问数端]
   （新增/改/删/测连通）         单一真相源                   （启动/调用时读取连库出数）
```

- **你（配置页）负责**：把连接配置写进共享 SQLite；提供新增/编辑/删除/测连通界面。
- **hermes-mcp 负责**：读这个 SQLite、连库、只读出数据。它不写这张表。
- 两处**指向同一个文件**，通过环境变量 `HERMESMCP_DB_CONFIG` 指定（默认 `<hermes-mcp>/db_connections.db`）。

## 2. 共享文件与路径

| 项 | 值 |
|---|---|
| 默认路径 | `<hermes-mcp>/db_connections.db` |
| 指定方式 | 配置页后端与 hermes-mcp 都读 `HERMESMCP_DB_CONFIG`；**两侧必须指向同一文件** |
| 并发 | SQLite 建议开 **WAL** 模式避免多进程读写锁冲突 |

> 若配置页与 hermes-mcp **不在同一台机器**，共享一个 SQLite 文件不成立——需要到那时再改 REST 同步或中心存储（届时另行对齐）。

## 3. SQLite 表结构（必须完全一致，DDL 见下）

数据库名：`db_connections`。列定义（与 `hermes-mcp/src/hermes_mcp/store.py` 的 `_SCHEMA` 逐一对应）：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | 主键 |
| `name` | TEXT **UNIQUE** | 连接名；问数工具参数 `connection` 用它标识 |
| `type` | TEXT NOT NULL | 方言：`sqlite` / `mysql` / `postgresql` / `sqlserver` / `oracle` |
| `host` | TEXT | 端点主机 |
| `port` | INTEGER | 端口 |
| `database` | TEXT NOT NULL | 库名/schema（sqlite 时为本地 `.db` 文件路径） |
| `username` | TEXT | 只读账号 |
| `password_cipher` | TEXT | **Fernet 加密后的密文**（见 §4）；空串=无密码 |
| `read_only` | INTEGER NOT NULL DEFAULT 1 | 只读标记；问数端只放行只读连接，默认恒为 1 |
| `max_rows` | INTEGER | 行数上限（默认 200） |
| `status` | TEXT | `ok` / `error` / `untested`（测连通结果） |
| `last_error` | TEXT | 最近失败原因，**打码**，不含密码/SQL 明文 |
| `created_at` / `updated_at` | TEXT DEFAULT datetime('now') | 审计 |

创建语句：
```sql
CREATE TABLE IF NOT EXISTS db_connections (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT NOT NULL UNIQUE,
    type            TEXT NOT NULL,
    host            TEXT,
    port            INTEGER,
    database        TEXT,
    username        TEXT,
    password_cipher TEXT,
    read_only       INTEGER NOT NULL DEFAULT 1,
    max_rows        INTEGER,
    status          TEXT,
    last_error      TEXT,
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at      TEXT NOT NULL DEFAULT (datetime('now'))
);
```

## 4. 密码加密（写进去必须是这个格式，否则问数端解不开）

- 派生：`key = base64.urlsafe_b64encode( sha256( HERMESMCP_DB_KEY.encode() ).digest() )`
- 加密：`密文 = Fernet(key).encrypt( password.encode() )` → 存入 `password_cipher`
- 解密：`password = Fernet(key).decrypt( password_cipher ).decode()`
- **缺 `HERMESMCP_DB_KEY` 时拒绝保存任何非空密码**（不落明文，不偷偷降级）。
- 同一个 key 全局唯一；key 丢失则历史密码不可解（只能重录）。

> 实现直接用：
> `from hermes_mcp.store import ConnectionStore`
> `store = ConnectionStore(path, enc_key=HERMESMCP_DB_KEY)` → `store.upsert(..., password=...)` / `store.get_record(name)` / `store.list()`。

## 5. 新增/编辑的密码三态（PUT 语义）

| 请求里的 `password` | 行为 |
|---|---|
| 非空字符串 | 加密为**新密码**写入 |
| `null`（不发该字段） | **保留旧值**不动 |
| 空字符串 `""` | **清除**密码（置空） |

## 6. 推荐的接口契约（与 hermes-mcp 问数端对齐的语义）

| 端点 | 行为 |
|---|---|
| `GET  /api/db-connections` | 列表；**永不返回密码**，只给 `has_password`（布尔）+ `status` |
| `POST /api/db-connections` | 新增；密码单独字段加密入库；重名返回冲突 |
| `PUT  /api/db-connections/{id}` | 更新；`password` 按 §5 三态 |
| `DELETE /api/db-connections/{id}` | 删除 |
| `POST /api/db-connections/{id}/test` | 试连通：用目标方言 driver 真连 + `SELECT 1`；成功写 `status=ok`（清 `last_error`），失败写 `status=error` + `last_error`（打码） |

**列表返回示例**（绝不能出现 password 明文/密文外的任何秘密）：
```json
{"connections": [
  {"name": "订单库", "type": "mysql", "host": "10.0.0.5", "port": 3306,
   "database": "shop", "username": "reporter", "read_only": true,
   "max_rows": 200, "has_password": true, "status": "ok", "last_error": null}
]}
```

## 7. 测连通实现建议

- 用与 `hermes-mcp/connections.py` 相同的 DSN 组装（`mysql+pymysql://` / `postgresql+psycopg://` / `mssql+pyodbc://` / `oracle+oracledb://` / `sqlite:///`）。
- 试连只做 `SELECT 1`；**超时**建议设连接层 5s，避免页面卡死。
- 连不上的错误信息**必须打码**：不含密码、不含整条连接串。

## 8. 安全红线（双方都守）

1. **列表/详情永不回显密码**，只有 `has_password`。
2. `last_error` / 日志不含密码、不含完整 DSN、不含 SQL 明文。
3. **推荐用 `SELECT-only` 数据库账号**（DB 侧只授读），这是「写不进去」的最硬保证。
4. `read_only` 默认恒为 `1`；问数端在语法白名单 + 事务 ROLLBACK 之上，还依赖这个标记做连接级只读判断。

## 9. 依赖与运行

- 配置页后端建议安装 `hermes-mcp` 包（`pip install -e <hermes-mcp目录>`）直接复用 `ConnectionStore`，避免复制加密/读表逻辑。
- 配置页后端需要咒语：`authlib`/`httpx` 等自己带；`cryptography` 由 hermes-mcp 依赖提供。
- 方言 driver（pymysql / psycopg / pyodbc / oracledb）在要**测连通**时就绪。
