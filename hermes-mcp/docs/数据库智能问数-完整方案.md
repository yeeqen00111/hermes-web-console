# Hermes 数据库智能问数 — 完整方案

> 版本：v0.3（待评审）  日期：2026-10-09
> 涉及工程：`hermes-mcp`（新建，独立 MCP Server）+ `hermes-dashboard-api-demo`（现有控制台，加「数据源配置」页）

---

## 1. 需求一句话

让用户在 **Hermes 对话框里用自然语言问数据库**（如「上月下单量」）。**SQL 生成与执行都在 hermes-mcp 服务端完成**（`ask` 工具：服务端调模型生成 SQL → 只读执行 → 返回数据+SQL）；Hermes 作为对话前端做意图澄清，并可选直接用 `query` 精细控制。数据库连接在一个可视化配置页里管理，落盘共享 SQLite。

## 2. 已确认需求

| 维度 | 决策 |
|---|---|
| 代码形态 | 独立 MCP Server（新建在 `hermes-mcp/`） |
| 目标数据库 | MySQL / PostgreSQL / SQL Server / Oracle（多方言） |
| 执行权限 | 只读安全 · 全部强化 |
| 问数入口 | Hermes 对话框直接用（对话前端，做意图澄清） |
| SQL 生成归属 | **服务端为主**：mcp-server 内 `ask` 生成 SQL + 执行；保留 `query` 供 Hermes 精细控制 |
| 生成模型 | **复用现有 custom 端点**（glm-5.3-flash，火山 ark），在 mcp-server 配置 |
| 配置入口 | 现有 Web 控制台加「数据源配置」页 |
| 连接存储 | 共享 SQLite（控制台写、mcp-server 读） |

> **🔒 硬约束：不改 Hermes 源码。** 本方案只新增自研组件（hermes-mcp + 控制台页），对 Hermes 仅「使用 + 只读其 config.yaml 取当前模型 + 注册 MCP 服务（配置项变更）」，**绝不修改 ../hermes-agent 任何源码**；沿用 `.claude/settings.json` 对 hermes-agent 目录的写保护 deny。

## 3. 架构（两组件 + 一共享存储）

```
┌─ 管理面：现有 Web 控制台（hermes-dashboard-api-demo）──────────┐
│  React 新增「数据源配置」页 ──/api/db-connections─▶ FastAPI 后端  │
│                                     CRUD + 测连通               │
│                                       │                        │
│                            共享 SQLite db_connections.db        │
└───────────────────────────────────────┬────────────────────────┘
                                        │ 读同一 SQLite
┌─ 问数面：hermes-mcp（独立 MCP Server）─────────────────────────┐
│  用户─自然语言▶ Hermes Agent（对话前端 · 意图澄清）              │
│                     │ MCP tools（ask / query / get_schema_map…） │
│                     ▼                                           │
│        ┌──────────────────────────────────────────────┐        │
│        │ ask(model)：NL→SQL 生成(glm-5.3-flash)→只读执行 │        │
│        │ query(sql)：白名单校验→ROLLBACK 事务执行          │        │
│        └──────────────────────────────────────────────┘        │
│                     │ 只读连接（SELECT-only 账号）                │
│                     ▼                                           │
│        MySQL / PostgreSQL / SQL Server / Oracle                 │
└───────────────────────────────────────────────────────────────┘
```

- **职责分离**：控制台管「连接配置写好、测通」；mcp-server 管「读配置、**生成 SQL、只读出数据**」；Hermes 管「对话与意图澄清」。
- **SQL 生成归属**：NL→SQL 主路径在 mcp-server（`ask` 内调配置的模型）；Hermes 可继续通过 `query` 绕过生成做精细控制。
- **安全边界**：mcp-server 持 DB 只读账号 + 生成模型的 key，与 Hermes 账号完全隔离。
- **传输**：默认 stdio（Hermes 同机拉起）；异机走 streamable-HTTP + 鉴权（见 §7、§10‑2）。

## 4. 数据模型：共享 SQLite `db_connections`

> 路径由 env `HERMESMCP_DB_CONFIG` 指定（默认 `hermes-mcp/db_connections.db`）；开 **WAL** 避免多进程锁冲突；两侧指向同一文件。

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `name` | 连接名（唯一；工具参数 `connection` 用它） |
| `type` | mysql / postgresql / sqlserver / oracle |
| `host` / `port` | 端点 |
| `database` | 库名/schema |
| `username` / `password_cipher`+`password_iv` | 只读账号；**密码用 env key 对称加密** |
| `read_only` | 默认 1，强制只读标记 |
| `max_rows` | 行数上限（默认 200） |
| `status` / `last_error` | 测连通结果；错误打码 |
| `created_at` / `updated_at` | 审计 |

安全规则：密码入库加密（key=`HERMESMCP_DB_KEY`）；GET 列表**永不回显密码**（只给 `masked` 标记）；`last_error` 不含密码/SQL 明文。

## 5. 控制台「数据源配置」页（接现有前后端模式）

**前端**（仿「模型配置」页）：列表（name/type/host→库/read_only/status）+ 新增 / 编辑 / 删除 / 测连通表单（host/port/database/username/password/read_only/max_rows）。

**后端新增端点**：

| 端点 | 作用 |
|---|---|
| `GET  /api/db-connections` | 列表（无密码，含 status） |
| `POST /api/db-connections` | 新增（密码单独字段，加密入库） |
| `PUT  /api/db-connections/{id}` | 更新（`password=null` 保留旧值，三态同模型 api_key） |
| `DELETE /api/db-connections/{id}` | 删除 |
| `POST /api/db-connections/{id}/test` | 真连 + `SELECT 1`，回写 status |
| `POST /api/db-connections/reload`(可选) | 通知 mcp-server 重载连接 |

## 6. MCP 工具（初始集）

所有工具首参 `connection`（连接名）。

| 工具 | 作用 |
|---|---|
| `ask` | **主入口**：`ask(connection, 自然语言问题)` → 服务端取 schema_map → 调生成模型产出 SQL → 只读执行 → 返回「数据 + 实际执行的 SQL + 统计」。生成失败自动带错误重试（限次） |
| `list_connections` | 列出连接（无密码，含 status） |
| `register_connection` | 运行时新增/更新（密码走 env 引用，拒裸 DSN 带密） |
| `remove_connection` | 移除 |
| `list_schemas` | 列出库/schema |
| `get_schema_map` | 表→字段+行数估算（NL→SQL 结构依据） |
| `describe_table` | 单表列/索引/外键 |
| `query` | 执行只读 SELECT，返回结果+截断/耗时标记（供 Hermes 精细控制/绕过生成） |
| `explain`(可选) | 执行计划 |

> `ask` 的生成模型在 mcp-server 内配置（复用 custom 端点 glm-5.3-flash）；`query` 保留让 Hermes 多步分析时直接给 SQL。两者都过同一套只读防线（§7）。

## 7. 只读安全强化（四层防线）

1. **语法白名单**：`sqlparse` 强制单语句；只放 `SELECT/WITH/SHOW/EXPLAIN/DESCRIBE`；拒 `INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/TRUNCATE/MERGE/CALL/GRANT`、`INTO OUTFILE`、`LOAD_FILE`、`@@`、注释裹隐藏语句。
2. **事务兜底**：显式事务执行 + **强制 `ROLLBACK` 永不 `commit`**；DB 侧 **SELECT-only 账号**双保险。
3. **资源限制**：`max_rows`(默认200) `fetchmany` 截断+`truncated` 标记；查询超时；字段/内容大小上限；语义安全时注入 `LIMIT`。
4. **外层**：密码加密入库、日志打码、`query` 审计（连接名+SQL+行数+耗时）。

失败返回结构化拒绝原因，不把 SQL 透传给 DB。

## 10. 决策与默认（2026-10-09 已确认）

> 下方各项已于 2026-10-09 经用户确认，可直接按此开写。

**10-0 代码形态** — ✅ 独立 MCP Server（`hermes-mcp/`）+ 现有控制台加配置页 + 共享 SQLite。**首期先建 SQLite 本地/内存样例库跑通全链路，再换真库。**

**10-1 只读账号** — ✅ 用专用 **SELECT-only 账号**（DB 侧只授 SELECT，第五道最硬保证）。

**10-1 只读账号** — 推荐：**用专用 SELECT-only 账号**。
数据库侧就只授 `SELECT`，是「写不进去」的最硬保证，与四层防线叠加为第五道。M1/M5 联调用它们。若暂时只连只读的测试/沙盒库，至少保证「平台侧不持有写权限账号」。

**10-2 传输方式** — ✅ **测试走 HTTP，正式打包装进 Hermes（stdio）**。开发/联调用 `scripts/run_http.py`（streamable-http，端口 9123，`http_probe_client.py` 验证）；**生产以 stdio 打包**注册进 Hermes（`python -m hermes_mcp.server`，由 Hermes 进程中拉起，`mcp_probe_client.py` 验证）。生产默认不暴露 HTTP 无认证端口；HTTP 仅作跨机/调试备选。两态均已实测可切。

**10-3 SQLite 路径/跨机** — ✅ 现阶段**控制台与 mcp-server 同机部署**，共用一个 `HERMESMCP_DB_CONFIG` 路径（默认 `hermes-mcp/db_connections.db`）。真到拆分跨机时再改 REST 同步/中心存储。

**10-4 密码加密 key** — ✅ 用**真实 env key `HERMESMCP_DB_KEY`**（生成随机口令写入 `.env.example`，生产换新）。缺 key 时拒绝保存密码，不做明文降级硬约束。

**10-5 首批库** — ✅ **先建 SQLite 本地/内存样例库跑通全链路**（方言待真库就绪），再换真库；真库用 SELECT-only 账号。

**10-6 SQL 生成** — ✅ **服务端生成为主**：`ask` 内取 schema_map → 调生成模型产出 SQL → 只读执行 → 返回数据+SQL。`query` 保留供 Hermes 精细控制。DB 账号 / 生成模型 key / Hermes 账号三方隔离。

**10-7 生成模型来源** — ✅ **跟随 Hermes 配置的模型**：mcp-server 加「模型解析器」——每次 `ask` 先读 **Hermes `config.yaml` 当前配置的默认模型**（路径 `HERMESMCP_CONFIG_PATH`）用它生成 SQL；读失败回退 `HERMESMCP_LLM_MODEL`（glm-5.3-flash）。零新增凭据、零对 dashboard 实时依赖。**M0 须实测**：在 Hermes 换（默认）模型后，config.yaml 是否被同步写回——决定「读配置」能跟随的实时程度（全局默认切换=跟得上；纯会话临时切=只反映配置文件默认）。

**10-8 生成模型 key** — ✅ `HERMESMCP_LLM_BASE_URL/API_KEY` 归 mcp-server 环境（.env，gitignore），复用现有 ark 端点；GitHub 公开仓库脱敏纪律沿用；仅 KEY 敏感，MODEL 随配置读跟随。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| Hermes 对 MCP-Server 接入方式未知 | M0 用最小 probe 先实测，禁止靠猜 |
| 跨机传输若走 HTTP 无鉴权 | HTTP 模式强制注入 token 鉴权，不开放无认证 |
| 加密 key 丢失→历史密码不可读 | key 独立备份；列表不回显，需重录 |
| 多方言 `EXPLAIN/SHOW/DESCRIBE` 语法差异 | 结构发现优先走标准 `information_schema`；方言专属能力挂适配层 |
| NL→SQL 生成质量不受控 | `ask` 内用 curated schema 上下文 + 业务口径字表 + 少量示例优化；返回附 SQL 供抽查；生成报错自动重试（限次）；事后日志复盘生成效果 |

## 12. 验收（M5 结束时）

1. 控制台能新增/编辑/删除/测通连接，密码不回显。
2. Hermes 对话框问「上个月 X 库订单量」→ 返回真实数据 + 可抽查的 SQL。
3. 注入/多语句/危险词 → 全部结构化拒绝，DB 无副作用。
4. 只读连接账号在 DB 侧确无写权限。
